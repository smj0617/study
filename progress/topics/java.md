## 학습 패턴
- 자주 틀리는 유형: 학습자가 덩어리 시작 위치를 틀림 (공백으로 시작하는 검색 문자열에서 기호 칸을 셈 — "100 - 20"→4, "1 + 2 + 3 + 4"→10)
- 학습자 특징: 비전공자 · 용어 정의를 정확히 따짐(기저 조건 vs 사례) · 기준을 끝까지 파고듦 (주관적 기준엔 만족 안 함) · 질문 범위가 공정한지 따짐 · 긴 설명 속 지나간 내용은 기억 못 함 · 문제 문장이 애매하면 막힘 · 배운 걸 "~라는 거지?"로 자기 말로 정리해 확인함 · 설명해보기에서 핵심 단계를 빠뜨리기 쉽지만 퀴즈(객관식)는 확실하게 맞힘 (2026-11-02)
- 잘 맞는 방식 (2026-11-01부터): 학습자가 완성 코드를 읽으며 질문하는 방식(하향식 — 완성품에서 필요한 곳만 내려감), 핵심만 10분 직접 짜기, 세션 30분 (시간 부족) · 사이드 질문은 학습자가 원하므로 제한 없이 끝까지
- Claude 가 지킬 것: 비유·그림으로 단계별 천천히 설명 (대화 기록 참고) · 한 번에 개념 1개씩 짧게 (학습자 요청, 긴 설명은 집중 방해) · 학습 중엔 먼저 묻지 않고 학습자 질문을 기다림 → 단계 끝에 놓친 것만 최대 5문항 확인 · 문제는 구체적으로 · 코드 위치를 물을 땐 코드를 같이 보여주기 · 새 용어는 지나가지 말고 학습자가 아는지 먼저 확인 · 앞의 표·코드를 가리킬 땐 그 부분을 다시 붙여 보여주기 (학습자는 스크롤을 올려 확인하면 집중이 깨짐)
- 실습: 학습자가 테스트 결과(expected/but was)만 보고 버그 2개를 스스로 찾아 고침 (TddPractice t1~t5)
