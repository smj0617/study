# E. 학습 진행 (계획 단계를 공부하는 대화)

A·D 로 세운 계획의 단계를 학습자와 공부할 때의 진행 방식. 기본은 **학습자가 완성 코드를 읽으며 질문하고, Claude 는 질문에 답하는 방식**이다. topic 파일의 `학습 패턴 > Claude 가 지킬 것`도 함께 따른다. 문항은 SKILL.md [문항 규칙]대로 낸다.

## E1 — 단계 시작

- `date` 로 시작 시각을 확인하고, 이번 단계 범위(파일·메서드)를 한 줄로 알린다.
- 세션은 기본 30분. 절반쯤 지나면 `date` 로 확인해 남은 시간을 한 줄로 알린다. 사이드 질문(E3)은 이 시간 제한으로 끊지 않는다.
- **예측 한 번** (사전 시험 효과 — 틀린 예측이라도 먼저 해 보면 뒤의 설명이 더 잘 남는다). 단계 시작에 한 번만, 건너뛸 수 있게 묻는다:
  > 이번 단계는 `<메서드·클래스 이름>` 이에요. 이름과 시그니처만 보고 무엇을 할지 한 줄로 예측해 볼래요? (틀려도 괜찮아요 · 패스 가능)
  - 이 메시지는 질문에서 끝낸다 (문항 규칙 2). 학습자가 답하면 첫 설명 덩어리에서 예측과 맞는 점·다른 점을 짚고, 패스하면 바로 E2 로 간다.
  - 학습자가 예측 질문을 빼 달라고 하면 `학습 패턴 > Claude 가 지킬 것`에 적고 다음부터 내지 않는다.

## E2 — 설명 덩어리

- 한 메시지에 개념 1개: 짧은 설명 + 작은 예시나 그림 하나. 대략 15줄 이내.
- Claude 는 메시지 끝에 질문하지 않는다 (E1 예측 질문만 예외). 덩어리를 보여준 뒤 학습자의 질문을 기다린다.
- 새 용어가 나오면 지나치지 않고 "<용어> 알아요?"를 한 번 묻는다. 학습자가 모르면 따로 한 덩어리(이름 + 설명 + 예시)로 가르친다. 한 줄로만 지나간 용어는 진도에 기록하지 않는다 (규칙 §2).
- 학습자가 단계가 끝났다고 알리기 전까지 다음 단계로 넘어가지 않는다.

## E3 — 사이드 질문 (`[사이드]`)

- 학습자가 `[사이드]` 를 붙이면 본 흐름과 별개 질문이다. 시간·길이 제한 없이 학습자가 원하는 만큼 따라간다. 단, 메시지 하나는 E2 크기로 짧게.
- 사이드 답이 끝나면 끊긴 본 흐름 메시지를 다시 보여준다:
  1. 사이드 질문이 본 메시지의 어느 `---` 덩어리와 관련 있었는지 한 줄로 먼저 말한다.
  2. 마지막 덩어리(답을 기다리던 덩어리)와 관련 있으면 그 덩어리부터만 다시 붙인다.
  3. 앞 덩어리와 관련 있거나 관련이 없으면 본 메시지 전체를 다시 붙인다.
- 사이드에서 따로 가르친 개념도 새 개념 기록 기준(규칙 §2)을 만족하면 세션 메모(E5)의 `다룸`에 넣는다.

## E4 — 단계 끝: 놓친 것 확인

- 학습자가 단계 끝을 알리면, 학습자의 질문이 다루지 않은 핵심만 골라 최대 5문항을 한 번에 하나씩 낸다 (문항 규칙).
- 그중 1문항은 **코드 읽기 문항**으로 낸다: 이번 단계 코드에서 그럴듯한 버그나 변경 하나를 코드와 함께 보여주고 "이렇게 바꾸면 어떤 테스트가 왜 깨질까?"를 묻는다 (또는 예측·추적). 결과는 `코드 읽기` 영역의 근거가 된다 (규칙 §4).
- 학습자의 질문이 이미 다 다뤘으면 "이번 단계는 질문으로 다 다뤘어요"라고 말하고 코드 읽기 문항 1개만 낸다 (패스 가능).

## E5 — 세션 메모

- 단계마다 E4 가 끝나면 topic 파일 `## 세션 메모` 에 한 줄 추가하고 SKILL.md [진도 저장] 을 한다 (`- 없음` 이 있으면 그 줄을 바꾼다):
  `- <날짜> <n단계> — 다룸: <따로 가르친 개념들> · 놓친 것 확인: <개념> 확실 / <개념> 애매 / <개념> 틀림(<학습자가 어떻게 답했나>) · 코드 읽기: <확실|애매|찍음|틀림>(<문항 요약>)`
- 여기서는 개념 상태를 바꾸지 않는다. 판정은 `/study done` 이 세션 메모를 근거로 한다. `/study done` 전에 대화가 끝나도 메모는 남는다.

## E6 — 직접 짜기 (계획의 마지막 직전 단계, `TODO(human)` 방식)

Claude Code Learning 스타일처럼, 설계 판단이 필요한 핵심 부분만 비워 두고 학습자가 채운다. 테스트가 채점한다.

1. **준비 (Claude)** — 완성 코드 프로젝트에서 연습 브랜치를 만든다:
   ```bash
   git -C <프로젝트 경로> branch --show-current        # 원래 브랜치 이름 기억 (보통 main 또는 master)
   git -C <프로젝트 경로> switch -c practice-<메서드>  # 이미 있으면 뒤에 -2
   ```
   핵심 메서드 몸통만 지우고 `// TODO(human): <무엇을 해야 하는지 한 줄>` 을 남긴다. 컴파일은 되게 반환값만 둔다 (예: `return 0;`, `return null;`). 테스트 파일은 건드리지 않는다. 그다음 `git -C <프로젝트 경로> commit -am "practice: <메서드> 비움"` — 원래 브랜치의 완성 코드는 그대로 남는다.
2. 학습자에게 알린다: 파일·메서드, `TODO(human)` 위치, 통과해야 할 테스트 이름, 제한 10분. IntelliJ 는 열린 프로젝트의 파일 변경을 스스로 반영한다.
3. 학습자가 IntelliJ 에서 테스트를 돌리면, Claude 는 `<프로젝트>/build/test-results/test/TEST-*.xml` 의 `tests`·`failures` 로 결과를 확인한다 (학습자가 원하면 Claude 가 flows/assignment.md D4 명령으로 직접 돌린다). 실패하면 Claude 가 먼저 설명하지 않고, 학습자가 실패 메시지(expected / but was)를 읽고 원인을 말하게 기다린다.
4. **힌트** (막혔을 때, 최대 2번): 답의 일부를 주지 않고 **더 구체적인 질문**으로 범위를 좁힌다 (예: "원래 출력 대상은 어느 줄에서 보관하죠?"). 2번 뒤에도 막히면 원래 브랜치의 정답을 보여주고 줄마다 설명한다.
5. 끝나면 `git -C <프로젝트 경로> switch <원래 브랜치>` 로 돌아간다 (연습 브랜치는 남겨 둠). 결과(통과 / 힌트 n번 / 정답 봄)를 세션 메모에 남긴다.

## E7 — 마무리

- 학습자가 오늘 학습을 마치면 `/study done` 을 안내한다 (하루 끝에 한 번, 개념마다 퀴즈 1문항, 최대 5개).
