# A. 학습 순서 추천 (`/study [자료]`)

SKILL.md 의 분기에서 넘어온 흐름. 진도 파일을 다루기 전에 progress-rules.md 를 Read 한다 ("규칙 §n").

## A1 — 진도 확인

1. `index.md` 를 Read 한다.
2. **주제 정하기**:
   - 자료가 인자로 왔으면 파일명·제목과 첫 부분(PDF는 1~3쪽, 웹은 제목·목차)만 보고 주제를 추정한다.
   - 아니면 AskUserQuestion 으로 묻는다 (index 의 주제들 + "새 주제").
   - 주제명·별칭으로 기존 주제와 같은지 먼저 확인.
3. **index 가 없거나 새 주제면** → [초기 진단] 후 topic 파일을 만들고 index 에 행 추가 (index 가 없으면 생성).
4. **기존 주제면** → `topics/<slug>.md` 만 Read 하고 (다른 주제 파일은 읽지 않음) 목표·영역별 실력·학습 중 개념·진행 중 계획을 3~5줄로 요약해 보여준다. 머리에 `- 목표:` 가 없으면 학습자에게 "이 주제를 왜 배우나요?"를 한 번 묻고 학습자의 말 그대로 적는다.

### 초기 진단

1. 학습자에게 "이 주제를 왜 배우나요? (예: 과제, 업무, 취업)"를 묻고 topic 머리에 `- 목표: <학습자의 말>` 로 적는다.
2. AskUserQuestion: "최근 Claude Code 대화 기록도 참고할까요?" (예 / 아니오) → **예**일 때만 [대화 기록 참고] 수행.
3. 자료가 인자로 왔으면 진단 전에 **자료의 목차만** 먼저 훑어서, 퀴즈와 개념 이름을 자료의 용어에 맞춘다.
4. **진단 퀴즈**: 자료와 관련된 영역을 최대 3개 고르고 (규칙 §4), 영역마다 1단계 → 5단계 문항 유형(규칙 §1 영역별 실력 표)으로 한 문항씩 낸다 (SKILL.md 문항 규칙). 틀리거나 "모름/패스"면 그 영역은 즉시 종료.
5. 영역별 실력과 개념 기록은 규칙 §4 "초기 진단 → 영역별 실력"대로 정한다 (맞힌 개념도 익힘이 아니라 학습 중 + `진단 확인`). 각 개념에 묶음과 지식 종류를 붙이고, 계수·다음은 `apply` 로 채운다 (규칙 §7).
6. `마지막 진단: 오늘 (이후 학습 세션 0회)`, `재진단 보류: 없음`.

### 대화 기록 참고 (선택)

- 대상: `C:/Users/sgosp/.claude/projects/*/*.jsonl` (Claude Code 대화만. claude.ai 웹 대화는 없음, 오래된 기록은 자동 삭제됨)
- 파일 전체를 Read 하지 말고 Grep 으로 주제 키워드만 검색.
- 매칭이 많으면 Agent(Explore) 에게 "사용자가 이 주제에 대해 무엇을 이해/혼동했는지 10줄 이내 요약"을 맡긴다.
- **보조 근거**일 뿐, 판정은 진단 퀴즈 우선.

## A2 — 복습 알림

1. 복습할 개념을 센다 (손으로 세지 않음):
   ```bash
   node C:/Users/sgosp/.claude/skills/study/scripts/progress.js due
   ```
   "복습할 개념 없음"이면 이 단계를 조용히 건너뛴다.
2. 알림을 보여준다:
   ```
   📌 복습할 게 있어요
   - java: 4개 (가장 오래 6일 지남)
   ```
3. AskUserQuestion 으로 선택하게 한다:
   - 가장 오래 밀린 것이 7일 이상 지났으면 첫 선택지를 **"복습 먼저 (추천)"** 로 둔다.
   - 선택지: **지금 빠르게 2개만** / **전체 복습 먼저 (`/study review`와 같음)** / **나중에 할게요**
4. 선택에 따라:
   - **빠르게 2개**: [flows/review.md](review.md) 를 Read 하고 현재 주제에서 최대 2개로 제한해 수행.
   - **전체 복습 먼저**: [flows/review.md](review.md) 전체를 수행.
   - 둘 다 끝나면 A3으로 이어간다.
   - **나중에**: 그대로 A3으로.

## A3 — 재진단·규칙 목록 확인

1. 규칙 §5 조건에 해당하면 AskUserQuestion 으로 제안. 승인 → 수행, 거절 → `재진단 보류: <오늘>` 기록.
2. SKILL.md [규칙 변경]의 고정 기간이 지났고 `rule-backlog.md` 에 항목이 있으면 "규칙 개선 목록 n개를 같이 정리할까요?"를 AskUserQuestion 으로 묻는다.

## A4 — 공부 자료 받기

- `$ARGUMENTS` 가 있으면 그것을 자료로 사용하고 A5 로.
- `$ARGUMENTS` 가 없고 현재 주제에 진행 중 계획이 있으면 AskUserQuestion: **계획 이어서 하기 (추천)** / 새 자료. 이어서 하기면 A5·A6 을 건너뛰고 [flows/session.md](session.md) 를 Read 해 **E. 학습 진행**으로 간다.
- 없으면 아래처럼 요청하고 **턴을 끝낸다** (다음 메시지에서 이어서 진행):
  > 공부할 자료를 주세요. 파일 경로, 웹 URL, 유튜브 링크, 또는 텍스트를 직접 붙여넣어도 됩니다.
- 상대 경로는 현재 작업 폴더 기준으로 찾고, 없으면 사용자에게 전체 경로를 묻는다.

## A5 — 자료 읽기 (종류별)

| 자료 | 판별 | 읽는 방법 |
|---|---|---|
| PDF | `.pdf` | Read 의 `pages` 로 최대 20쪽씩. 10쪽 초과면 먼저 1~3쪽(목차)으로 구조 파악. |
| 텍스트/문서 파일 | `.md` `.txt` `.py` 등 | Read. 2000줄 초과면 "긴 자료" 처리. |
| Word/PPT | `.docx` `.pptx` | anthropic-skills 의 docx/pptx 스킬 텍스트 추출 방법 사용. |
| 웹페이지 | `http(s)://` (유튜브 제외) | WebFetch 로 "목차와 핵심 개념" 추출. |
| 유튜브 | `youtube.com` / `youtu.be` | 아래 [유튜브 자막]. |
| 붙여넣은 텍스트 | 그 외 | 그대로 사용. |

### 유튜브 자막

1. 자막만 받는다 (영상 다운로드 금지), 임시 폴더에 저장:
   ```bash
   uvx yt-dlp --skip-download --write-auto-subs --write-subs --sub-langs "ko,en" --sub-format vtt -o "<임시폴더>/%(id)s.%(ext)s" "<URL>"
   ```
   처음 실행 시 uvx 가 PyPI 에서 yt-dlp 를 받는다는 점을 한 줄로 알린다.
2. `.vtt` 에서 타임스탬프·중복 줄을 제거하고 읽는다.
3. 자막이 없거나 실패 → 사용자에게 자막 텍스트(유튜브 "스크립트 표시")를 붙여달라고 요청.

### 긴 자료 (PDF 50쪽 초과, 텍스트 2000줄 초과, 자막 1시간 이상 등)

본문을 대화에 올리지 않고 Agent(general-purpose) 에게 맡긴다:
> "<자료>를 끝까지 읽고 다음만 반환: ① 장/절 목차 ② 각 장의 핵심 개념 3~5개 ③ 장 사이 선수지식 관계 ④ 장별 난이도(1~5). 원문 인용 금지."

## A6 — 학습 순서 추천

topic 파일의 목표·상태별 개념·표시·학습 패턴과 자료 구조를 비교한다.

1. **목표에 맞추기**: topic 의 `목표`에 직접 쓰이는 부분을 앞에 두고 비중을 높인다. 목표와 거리가 먼 부분은 훑기나 건너뛰기로 둔다 (이유 명시).
2. **빠르게 훑기**: 익힘·정착·압축 상태 개념이 나오는 부분.
3. **확인 위주**: `진단 확인` 개념 — 학습자가 짧게 읽고, Claude 가 `/study done` 에서 설명해보기로 확인.
4. **맨 앞에 배치**: 자료가 전제하지만 학습자가 모르는 선수지식 (자료 밖 개념이면 명시). 개념에 `선수:`가 있으면, 선수 개념이 모두 익힘 이상인 개념부터 배치한다 (지식 공간 이론: 지금 배울 준비가 된 것부터).
5. **비중 높이기**: 학습 중 개념, `오개념`·`설명 누락` 표시가 있는 개념, `자주 틀리는 유형`에 해당하는 장, `나중에 볼 목록`의 항목이 나오는 장.
6. **뒤로 미루기**: 관련 영역의 실력보다 2단계 이상 어려운 장 (이유 명시). 장별 난이도는 내용으로 추정하고, 자료가 짧아 난이도 차이가 뚜렷하지 않으면 이 규칙은 적용하지 않는다.
7. **충돌 시 우선순위**: 오개념 교정 > 선수지식 > 목표 > 미루기. 오개념이 있는 개념이 어려운 장에 있으면 미루지 않고, 그 장에서 오개념 부분만 앞쪽 단계로 뽑는다.
8. **방식**: `학습 패턴 > 잘 맞는 방식`이 있으면 그것을 따른다. 없을 때만 관련 영역 실력으로 고른다 — 1~2단계 또는 미진단이면 풀이 예제 먼저(완성 코드 읽기), 3단계 이상이면 문제 먼저(직접 짜기 비중을 늘림) (전문성 역전 효과).
9. 개념에 묶음을 붙일 때 기존 묶음 이름을 재사용한다.

출력:

```
## 추천 학습 순서 — <자료명>
목표: <topic 의 목표>
관련 영역 실력: <영역> <단계> · <영역> 미진단 · …

| 순서 | 범위 | 목표 | 방식 | 예상 시간 |
|---|---|---|---|---|
| 1 | ... | ... | 집중 / 훑기 / 실습 | ... |

건너뛸 부분: ...
미뤄둔 부분: ... (이유)
첫 번째로 할 일: <지금 바로 시작할 구체적 행동 1개>
공부를 마치면 `/study done` 으로 진도를 기록하세요.
```

마지막으로 topic 파일의 `진행 중 계획`에 자료(전체 경로/URL)와 단계 목록을 `0/N단계`로 기록하고 `sync-index <slug>` 로 index 행을 맞춘다.
- 기존 계획이 있으면(`없음`이 아니면) 교체 전에 AskUserQuestion 으로 확인.
- `없음 (최근 완주: …)` 이면 묻지 않고 새 계획으로 바꾼다.
- 학습자가 바로 공부를 시작하면 [flows/session.md](session.md) 를 Read 해 E 로 이어간다.
