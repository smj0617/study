# 흐름 시나리오

모두 `fixtures/progress` 사본, 날짜 2026-11-10 기준. 돌리는 방법은 [README.md](README.md).

## 1. 복습 순서와 개수 — `/study review`

- 상황: 학습자가 `/study review` 실행. 문항마다 학습자는 정답 + 확실로 답한다.
- 기대:
  - [ ] `due sample` 을 실행하고, 그 순서대로 위에서 5개만 고른다: 학습 확신오류 → 익힘 누락 → 학습 진단 → 익힘 21일 → 익힘 1일.
  - [ ] "남은 복습 1개"를 요약에 적는다.
  - [ ] 학습 확신오류는 오개념[실행 순서] 지점을, 익힘 누락은 빠진 "이유"를 다시 묻는다.
  - [ ] 문항을 하나씩 내고, 문항마다 확신도를 묻는다.
  - [ ] 판정마다 `apply` 를 실행하고 (학습 중 개념은 설명해보기 통과 시 `--explained`), 끝에 `sync-index sample --studied` 와 `check` 를 실행한다.

## 2. 개념 지식의 문항 형식

- 상황: 시나리오 1에서 "학습 진단"(개념 · 깊이 미판정)에 낼 퀴즈 문항.
- 기대:
  - [ ] 객관식이 아니다 (예측·추적·버그 찾기·한 줄 단답 중 하나).
  - [ ] "왜 / 무엇과 어떻게 연결되나"를 묻는 문항이다.
  - [ ] 메시지가 질문과 확신도 묻기에서 끝난다 — 뒤에 힌트·예시 답·"~를 생각해 보세요"가 없다.

## 3. 세션 메모를 근거로 한 `/study done`

- 준비: 사본의 `## 세션 메모` 를 `- 2026-11-10 2단계 — 다룸: 확인전 개념 · 놓친 것 확인: 확인전 개념 확실 · 코드 읽기: 애매(조건 뒤집기)` 로 바꾼다.
- 상황: 학습자가 `/study done` 실행. 설명해보기에서 틀린 내용 없이 설명한다.
- 기대:
  - [ ] "세션 메모 기준으로 2단계까지 맞죠?"처럼 메모로 범위를 확인한다.
  - [ ] 확인전 개념은 놓친 것 확인 '확실'을 퀴즈로 인정해 설명해보기만 하고, 추가 퀴즈를 내지 않는다.
  - [ ] `apply sample "확인전 개념" 확실 --explained` 로 익힘에 넣는다 (나중에 볼 목록에서 빠짐).
  - [ ] 로그 끝에 `코드 읽기 0/1` 처럼 코드 읽기 결과를 붙이고, 세션 메모를 `- 없음` 으로 비운다.

## 4. 문제 오독

- 상황: 복습 중 학습자가 '확실'로 답했는데 틀렸고, 이어서 "아 문제를 잘못 읽었어"라고 한다.
- 기대:
  - [ ] 바로 판정하지 않고, 같은 지점을 다른 문장으로 한 번 더 묻는다.
  - [ ] 다시 물은 답으로 판정한다. 다시 물어 맞혔으면 `--sure` 를 붙이지 않는다 (첫 답은 확신 오류로 치지 않음).

## 5. 학습 진행의 질문 규칙 — E 흐름

- 상황: 진행 중 계획 "샘플 자료" 2단계를 시작한다. 학습자는 예측을 "패스"한다. 이후 학습자가 질문 2개를 하고 "단계 끝"이라고 한다.
- 기대:
  - [ ] 단계 시작에 예측 질문을 한 번만 내고, "패스 가능"을 붙이고, 질문에서 메시지를 끝낸다.
  - [ ] 패스 뒤 설명 덩어리 메시지들은 끝에 질문이 없다.
  - [ ] 단계 끝 놓친 것 확인은 최대 5문항이고, 그중 1문항은 코드를 붙인 코드 읽기 문항(버그 찾기·예측·추적)이다.
  - [ ] 끝나면 세션 메모 한 줄(코드 읽기 결과 포함)을 쓰고 진도 저장(커밋 메시지 `memo: …`)을 계획한다.
